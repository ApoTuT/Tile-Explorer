## 部署结构

新站使用独立的 `tile-explorer-preview.service`，开机启动并在异常退出时重启。它运行 Python 标准库静态服务，监听 80 端口；已有展示平台继续运行于其原端口。游戏不依赖开发电脑，不需要数据库或规则后端。

目录为 `/home/codex/apps/tile-explorer/`。每个构建上传到 `incoming/构建号/`，核对归档与所有文件后复制到 `public/tile-explorer/releases/构建号/`。`current.json` 只记录正式构建号。发布分两步：先 `stage` 部署独立版本并验收，再 `activate` 原子替换入口指向。

可复现命令：本地执行 `python tools/release_v07.py package`，上传生成的压缩包、清单、SHA256SUMS，以及 `tools/preview_v07_server.py` 和 `tools/install_v07_preview.sh`。然后在新服务器运行：

```sh
bash incoming/20261027-v07r3-882617f7/install_v07_preview.sh stage 20261027-v07r3-882617f7
# 完成不可变地址验收后：
bash incoming/20261027-v07r3-882617f7/install_v07_preview.sh activate 20261027-v07r3-882617f7
```

上述命令以 `/home/codex/apps/tile-explorer/` 为当前目录。密码仅用于交互式服务器认证，没有写入仓库、脚本、静态包或服务配置。

## 回退与限制

这是该新主机上的首次游戏部署，没有可直接切回的旧游戏构建。以后更新时，激活前会把旧指向保存在新构建目录的 `current.before.json`；恢复该指向即可回退，不必移动不可变目录。首次部署若需撤回，可停止独立游戏服务，已有展示平台不受影响。

旧 IP 上的不可变地址不会自动跳转到新 IP；用户应使用本记录的新地址。浏览器存档按站点保存，旧 IP 的本地进度不会自动迁移。尚未做真实手机硬件测试和陌生玩家 5–10 分钟计时试验。
