# v0.2 技术方案：候选槽小剧场

整理日期：2026-10-20。状态：**方案待实施**。基于正式 `v0.1` 基线继续迭代。

本文描述计划采用的实现方式，不代表相关代码、音频或动画已经存在。本文编写期间未运行本版测试、制作素材或实现功能。玩家体验与内容清单见 [迭代更新记录](../ITERATION_LOG.md#v02候选槽小剧场规划中)。

## 1. 目标与范围

为现有 18 种牌提供专属入槽声音、性格动作和表情，配置 6 组双牌互动、2 组三种不同牌的互动，并补齐三同消除的退场表现。

组合只驱动视听反馈，不影响得分、七格容量、同类自动靠拢、三同消除、胜负或工具行为。角色和剧本使用静态配置、本地资源，不依赖在线模型或新增游戏运行框架。

本版继续使用 Python 标准库服务与原生 JavaScript 页面。运行时数据结算由 Python 负责，前端负责把结算事实编排成表演。

## 2. 当前实现与接入问题

| 当前位置 | 现状 | 本版需要处理的问题 |
|---|---|---|
| [engine.py](../../tile_explorer/engine.py) 的 `Game.pick()` | 同一次调用完成入槽、三消和胜负判断 | 返回状态中可能已没有第三张牌，需要提供消除前的瞬时数据 |
| [engine.py](../../tile_explorer/engine.py) 的 `Game.magic()` | 调用 `pick(..., penetrate=True)`，当前不返回结果 | 需要透传同一份表现事件 |
| [server.py](../../tile_explorer/server.py) 的 `do_POST()` | 成功操作直接返回最终状态 | 需要在成功操作响应中附加一次性事件 |
| [app.js](../../web/app.js) 的 `perform()` | `state=data` 后立即 `render()` | 需要分开接收权威状态与表现事件，并管理取消和去重 |
| `renderTray()` | 每次 `replaceChildren()` 重建全部槽内容 | 长驻角色动作会中断，需要稳定实例节点 |
| `symbolSvg()` 与 [style.css](../../web/style.css) | 图集加载后隐藏回退 SVG；`.tile-art` 自带放大变换 | 表情不能只修改回退 SVG，动画不能覆盖图集缩放 |
| `server.py` 静态资源映射 | 只登记现有 HTML、JS、CSS、PNG | 新脚本与音频需要登记允许访问的资源和 MIME |

实现前以实际代码位置为准；以上函数名用于定位，不依赖固定行号。

## 3. 模块划分

| 模块 | 计划职责 |
|---|---|
| `tile_explorer/engine.py` | 在既有结算过程中收集入槽、三消事实，作为方法返回值 |
| `tile_explorer/server.py` | 将事件附加到对应成功响应，提供本地素材 |
| `web/app.js` | 连接请求、状态渲染、候选槽角色节点与调度器 |
| 新增 `web/tray-content.js` | 角色配置、剧本配置、声音资源清单和动作预设引用 |
| 新增 `web/tray-director.js` | 选择剧本、绑定演员、处理优先级、冷却、取消和事件去重 |
| 新增 `web/audio-manager.js` | 音频解锁、缓存、并发、音量和停止管理 |
| `web/style.css` | 槽位分层、动作包装、表情与减少动态效果的样式 |
| `web/index.html` | 按依赖顺序加载脚本，提供音效开关 |

新增脚本沿用普通 `defer` 脚本方式，使用单一命名空间组织导出，避免散布全局变量。内容配置先加载，再加载音频和调度器，最后启动 `app.js`。

## 4. 后端表现事件协议

### 4.1 产生时机

在 `Game.pick()` 的现有结算过程中，依次采集：

1. 校验成功并插入暂存槽后，记录 `tray_enter`。
2. 移除三张同类牌前，记录 `triple_clear` 的成员。
3. 按现有顺序完成分数和胜负结算，再返回事件集合。

`tray_after_insert` 必须复制成独立的列表与牌数据，不能引用随后被修改的槽列表。表现事件不进入 `Game.state()`，也不写入牌局或完成记录。

### 4.2 响应结构

成功响应保留现有顶层状态字段，新增可选字段：

```json
{
  "presentation": {
    "schema_version": 1,
    "events": [
      {
        "type": "tray_enter",
        "tile": {"id": 12, "kind": 0},
        "insert_index": 2,
        "tray_after_insert": [
          {"id": 3, "kind": 0},
          {"id": 8, "kind": 0},
          {"id": 12, "kind": 0}
        ]
      },
      {
        "type": "triple_clear",
        "kind": 0,
        "tile_ids": [3, 8, 12]
      }
    ]
  }
}
```

上例只展示新增字段。索引均从 0 开始；该例最终真实槽为空，但事件保留了第三张入槽时的三牌位置。

| 场景 | 事件处理 |
|---|---|
| 普通取牌、魔法取牌成功 | 返回入槽事件，若成组则另附三消事件 |
| 撤回、重排、重开、选关、下一关 | 返回状态即可，由前端清理对应旧表演 |
| 初次加载、刷新、`GET /api/state` | 不返回历史事件 |
| 参数或规则错误 | 沿用错误响应及状态，不附成功表演事件 |

`magic()` 必须返回 `pick()` 的结果。响应缺少 `presentation`、版本不受支持或事件结构不合法时，前端只更新状态并跳过表演，游戏仍能继续。

## 5. 角色与剧本配置

### 5.1 角色配置

角色以 `state.symbols[kind].code` 映射，不把数字 `kind` 固定写进内容表。每种牌至少配置：

| 字段 | 含义 |
|---|---|
| `code` | 稳定类型，如 `apple`、`cat`、`train` |
| `personality` | 制作人员理解角色的性格描述 |
| `enter_sound` | 本地入槽声音 ID |
| `enter_motion` | 入槽动作预设 ID |
| `reaction_anchor` | 表情贴纸的相对锚点 |
| `clear_motion`、`clear_sound` | 三消退场动作与声音引用，可复用分类预设 |
| `idle_motion` | 可选的低频、无声动作 |

未知类型采用轻弹动作和通用短音。图集、声音、贴纸任一资源不可用时，允许分别降级。

### 5.2 剧本配置

每个剧本至少配置 `id`、所需 `codes`、允许的 `initiators`、`priority`、`cooldown_ms`、`duration_ms` 和 `cues`。演员用角色槽引用实际 `tile.id`；台词、声音或动画不能依据类型定位到所有同类牌。

`cues` 只引用受控动作和音频 ID，不执行动态脚本或任意配置字符串。

首批规则与可共现关卡：

| 剧本 ID | 所需类型 | 关卡 |
|---|---|---|
| `cat_inspects_apple` | `apple`、`cat` | 1–3 |
| `car_startles_cat` | `car`、`cat` | 1–3 |
| `banana_hails_taxi` | `banana`、`taxi` | 3–6 |
| `dog_greets_bus` | `dog`、`bus` | 4–6 |
| `rabbit_inspects_grape` | `grape`、`rabbit` | 5–9 |
| `train_wakes_panda` | `train`、`panda` | 7–9 |
| `first_trip` | `apple`、`car`、`cat` | 1–3 |
| `sleepy_fruit_train` | `grape`、`train`、`panda` | 7–9 |

范围来自现有 `make_level()` 的图案分配。共现范围不等于每条普通点击路线都能触发；实施时需要记录一条可复现取牌路线。

## 6. 组合匹配与调度

### 6.1 匹配步骤

每次成功取牌只进行一次选择：

1. 验证新牌、事件、当前场景和本次响应一致。
2. 本次若有三同消除，选择三消表演，跳过组合匹配。
3. 否则在最终真实槽中寻找包含新牌的剧本；无需相邻。
4. 先匹配三种不同牌的剧本，再匹配双牌剧本。
5. 排除冷却中的规则，再按配置优先级和规则 ID 稳定排序。
6. 同类演员有多个时，选与新牌槽位距离最近者；距离相同按槽位索引选择。
7. 未选中剧本时播放普通入槽反馈。

成功入槽始终有基础动作。组合剧本包含新牌的声音标识，不再额外叠播完整普通入槽声音。三消也包含第三张的短反馈，避免同一操作重复播放多段声音。

### 6.2 初始节奏参数

| 项目 | 初始值 |
|---|---:|
| 普通入槽 | 120–180 毫秒 |
| 双牌互动 | 300–450 毫秒 |
| 三牌互动 | 450–600 毫秒 |
| 三消退场 | 180–250 毫秒 |
| 全局组合间隔 | 1000 毫秒 |
| 同剧本冷却 | 6000 毫秒 |
| 音频并发声部 | 最多 2 个 |

冷却使用单调时钟，并在剧本真正开始时记录。表演调度与游戏规则使用不同状态，不能因冷却阻止取牌或消除。以上均为待试玩调整的初始参数。

## 7. 候选槽渲染

### 7.1 三层结构

1. **槽位层**：固定七格背景，保留容量和位置语义。
2. **角色层**：以 `tile.id` 建立节点映射，按最终槽序移动或删除节点。
3. **特效层**：显示贴纸、装饰和短暂三消副本，设置 `pointer-events: none`。

外层位置包装负责自动靠拢；内层动作包装负责倾斜、弹跳、缩放；最内层 `.tile-art` 保留原有图集位置和 `scale(1.42)`。不同层各自管理变换，避免互相覆盖。

牌面容器继续裁切图集边缘。跨槽贴纸和装饰放在独立特效层，避免受到当前 `.tray-slot.filled { overflow: hidden; }` 裁切。表情不能遮住类型辨认区域、槽位计数或棋盘可点击牌。

### 7.2 三消瞬时状态

前端立即采用后端最终状态，不为等待动画而延迟真实移除、槽位计数、分数或结果面板。使用 `tray_after_insert` 在特效层建立三张临时副本，播放退场后清理。

副本不加入真实角色映射，不接受输入，不参与下一次组合。新操作到来时，可以提前淡出旧副本；同时存在的临时副本最多一组三张，防止快速三消积累节点。

### 7.3 表情素材

v0.2 先以惊叹号、汗滴、爱心、音符、困倦符号等 SVG 贴纸表达情绪，配合现有图案整体动作。图集加载后回退 SVG 不可见，因此不能仅改回退 SVG 的眼睛或嘴巴实现表情。需要独立器官动作时另行增加素材并登记来源。

## 8. 操作与生命周期

当前 `busy` 继续只控制接口请求，动画不延长 `busy`。前端用 `sceneEpoch` 标识当前牌局，用单调递增 `actionSeq` 标识请求；两者共同组成一次表现批次键，已消费批次不重复播放。

| 触发 | 处理 |
|---|---|
| 新取牌请求 | 停止可打断的旧组合；成功后按新状态选择一次表演 |
| 撤回 | 清理正在播放的组合和相关临时副本，按返回状态移除被撤回演员 |
| 重排、重开、切关、下一关 | 递增场景代号，取消动作、声音和定时器，清空演员缓存后重建 |
| 音效关闭 | 立即停止音频，动作可以完成 |
| 页面隐藏 | 取消演出并暂停音频，不积攒待播放队列；后台返回的响应照常同步状态，但将表现批次标记为已消费并丢弃 |
| 返回前台 | 展示当前状态，下一次有效用户操作时恢复音频，不补播历史 |
| 接口错误 | 不演出成功反馈，优先应用错误响应中的权威状态 |
| 连接中断 | 不自动重复提交取牌；恢复时通过状态读取重新同步 |
| 视口变化 | 重新计算位置，取消依赖旧坐标的装饰与副本 |

接收事件和实际起播时都检查页面可见性；后台事件不进入待播队列，返回前台后也不能再次消费。所有定时回调开始前重新检查页面可见性、场景代号、牌 ID 和取消状态。动画完成、取消、资源失败三条路径都要执行清理。

## 9. 音频与静态资源

使用单个 `AudioContext`，通过主增益节点控制音量，缓存已解码短音。首次有效点击时创建或恢复上下文，不能等取牌请求完成后才尝试解锁。播放前检查可用状态，失败时继续无声游玩。

资源管理原则：

- 声音使用本地短音，优先预载当前关卡涉及的类型；解码完成前不延后补播过期声音。
- 组合优先于普通入槽声音；并发超过上限时停止或跳过低优先级声部。
- 音效开关保存在独立设置键，例如 `tile-explorer.settings.v02`，读写失败时使用内存默认值，不影响牌局存档。
- 新增压缩音频和装饰资源初步预算控制在 2 MB 内，交付时记录实际体积。
- 资源表登记声音 ID、文件路径、时长、音量、制作或授权来源，避免从其他游戏直接提取声音。
- `server.py` 为必要脚本及音频登记白名单和 MIME，例如 MP3 对应 `audio/mpeg`；不因加载素材而开放任意项目目录。
- 当前 `Cache-Control: no-store` 可先沿用；资源缓存策略需要调整时单独评估，不依赖浏览器磁盘缓存保证功能。

浏览器依据：[Chrome 自动播放说明](https://developer.chrome.com/blog/autoplay/)、[Web Audio 最佳实践](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)。兼容性须以目标浏览器实测为准。

## 10. 降级与可访问性

- 音频、贴纸或动画失败时，权威状态继续正常显示。
- 响应缺少表现事件时退回普通槽位渲染。
- 尊重 `prefers-reduced-motion`，关闭持续摇晃、位移和缩放，改用短暂静态表情或亮度提示；JavaScript 动画也要读取该设置，不能只关闭 CSS transition。
- 装饰层使用 `aria-hidden`，不把每次声音或表情变成屏幕阅读器播报。
- 保留牌型和槽位的现有可访问名称，声音不承载独有规则信息。

### 实际浏览器与内容

- 覆盖桌面 Chrome/Edge、Android Chrome、iOS Safari；设备不可用时明确记录未测。
- 为 18 种入槽反馈和 8 组互动记录复现方式。
