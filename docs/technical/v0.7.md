# v0.7 正式版设计：三十关，滑出新花样

日期：2026-10-24。状态：**已实现，Linux/Windows CI 及本地、线上验收通过，已发布公网**。[正式试玩](http://106.12.167.253/tile-explorer/)，[发布记录](v0.7-deployment.md)。

本文保留设计依据；实际落地的棋盘规模、配料调整、数据格式与验证证据以 [v0.7 实现记录](v0.7-implementation.md)及[30 关规格](v0.7-levels.md)为准。

v0.7 定位为当前 v0 系列的正式内容版：沿用 v0.6 已成型的操作、素材和合成链，扩展为 30 关、90 星，并在 **第 15、20、25 关首次引入三个新机制**。本文件规定产品与技术规则；[30 关规格](v0.7-levels.md)逐关规定材料、目标、尺寸和出题意图。实际坐标、参考解与三星回放已写入 `web/slide-v07/levels.js`，[完整空间报告](v0.7-level-report.json)覆盖全部 36 个变体。

## 1. 版本目标与已有基础

玩家体验目标：先学会让路和停靠，再学会改变通路、创造停点和借道穿行，最终能主动规划一次漂亮的连续合成。

本次核对的代码基线为 `web/slide-v06/`，规则标识 `slide-v06-3`、评分标识 `score-v06-1`。以代码为准；历史 README、报告和 v0.6 文档含不同迭代的数据，不把其中的状态数量或最短步数当作 v0.7 的证明。

| 保留基础 | v0.7 的约定 |
|---|---|
| 选中一块、四向滑到头 | 一次有效滑动计一步；无效操作不扣步 |
| 同链同级、整边对齐合成 | 产物留在被撞块位置；达到本关目标等级才交付 |
| 三条升级链 | 水果：荔枝→橘子→苹果→桃子→西瓜；植物：种子→嫩芽→小树→大树；汽车：小汽车→跑车→超跑 |
| 大小块 | 每条链在同一关固定为 1×1、2×1、1×2 或 2×2；升级不变大、不旋转 |
| 障碍布置和有限挪动 | 放置零步，确认后移动一格计一步并消耗一次障碍额度 |
| 每关 20 步、无倒计时 | 第 20 步完成仍判胜；失败后可免费撤销和重试 |
| 连击、积分、完整撤销、提示 | 保留现有计分公式；新地形效果自身不额外计分、不增加连击 |
| 完整矩形棋盘 | 图案继续作为背景主题；不重新引入易产生死角的异形边界 |

发布范围包括 30 关、三项新机制、完整预览、可靠恢复、90 星收集与终章结算。新增美术只需少量角标、地形和反馈。继续使用现有原生 JavaScript、DOM/CSS 和静态 H5 架构，不为内容扩展更换引擎。

不纳入此版：第四条合成链、计时模式、养成经济、付费救援、联网排行榜、无限随机地图。难度主要来自顺序和落点，不靠堆牌或隐藏规则。

## 2. 头脑风暴与选型

下列均为原创设计候选，不表示已实现。选择标准是：是否改变玩家的具体决策、能否提前看懂、能否可靠验关、能否复用已有操作。

| 创意 | 新的决策 | 可解性或实现代价 | 本版处理 |
|---|---|---|---|
| 爆破卡 | 把合成安排在哪里，才能炸开关键通路？ | 需要明确范围、可破坏对象与爆后停靠条件 | **第 15 关首发** |
| 一次性停靠花台 | 哪张牌先用掉中途停点？ | 增加有限地形状态，操作仍是滑动 | **第 20 关首发** |
| 成对传送门 | 哪张牌值得占用一次跨区机会？ | 需验证出口占位、大块尺寸和门的消耗 | **第 25 关首发** |
| 磁力卡 | 合成时把同一行最近的同类吸来一格 | 多目标选择和部分接触容易难以预测 | 备选，先做规则小样 |
| 彩虹卡 | 把一次万能配对留给哪个等级？ | 改变材料数量，容易成为无脑最优解 | 后续独立验证 |
| 冰封材料 | 先在旁边合成解冻，还是先挪路？ | 容易变成固定解锁顺序 | 暂存 |
| 单向风道 | 利用固定方向的二次滑动改变路线 | 一次操作多段运动，预览负担较高 | 暂存 |
| 回声卡 | 合成后在原位留下可停靠一次的虚影 | 需要解释持续时间和回收条件 | 暂存，可作为未来花台变体 |
| 双面卡 | 消耗一步切换同等级的另一条链 | 破坏每条链的材料守恒 | 暂存 |
| 接力钥匙 | 指定合成远程打开闸门 | 与爆破的开路收益接近，容易重复 | 不与爆破同时首发 |
| 加步卡 | 选择何时换取两步余量 | 更像缓冲道具，缺少空间决策 | 不纳入主线 |
| 旋转台 | 旋转 2×1 大块穿过窄路 | 改变尺寸假设，碰撞和素材范围扩大 | 留待下一大版 |

三项入选机制分别作用于“障碍”“停止位置”“跨区通行”。它们共享四向滑动，但不会只是三种不同颜色的消除奖励。每五关只引入一个新概念，末段再组合。

## 3. 三十关节奏

| 关段 | 玩家学会的事情 | 难度安排 |
|---|---|---|
| 01–05 | 一滑到底、升级、借位、横块让路 | 极易→简单；每关一个明确知识点 |
| 06–10 | 竖块、障碍移动、2×2 大块、完整升级链 | 中等；第 10 关完成基础毕业考 |

| 16–19 | 爆破位置、清路顺序、保留停靠点 | 逐步提高；第 19 关是爆破章考核 |
| **20** | **停靠花台教学** | 回落；单链小盘，只教一个新判断 |

全部关卡保留 20 步。表中的解题步数区间是关卡创作目标，不是已测最短解。教学关留出充足余量；高难关目标参考解控制在 14–17 步，至少留 3 步余量。若布局只能靠 19–20 步唯一解通过，优先改布局，不先加步数或发救援。

主线按通关解锁下一关，重玩不限；三星不作为解锁条件。章节分别覆盖 01–05、06–10、11–15、16–20、21–25、26–30。第 30 关结束显示“30 关完成”，允许继续补星。调试选关与玩家进度分离。

## 4. 第 15 关：爆破卡

### 4.1 卡牌与爆炸规则

爆破卡是一张普通材料附带的单次能力，例如“爆破苹果”。原图案和等级始终可见，角上增加炸弹标记；它仍只能与同链同级材料合成。任一参与者有爆破标记，本次成功合成后触发一次爆炸，能力随即消耗，产物不继承标记。

爆心为**合成产物在被撞块位置占据的整个矩形**。爆区是该矩形外侧上、下、左、右各一格的边缘带，不含四个斜角；裁掉棋盘外格。对 2×2 产物也按整个矩形计算，不能只从左上角扩散。

爆炸摧毁爆区内所有“易碎木箱”方块。木箱固定、1×1、阻挡滑动、无法合成；一次爆炸全部清除，不做耐久、不掉落新牌、不产生二次连锁。石块、可挪障碍和普通合成材料不受伤，花台与传送门也不被爆炸消耗。同一次合成若双方均有爆破标记，仍只爆一次，不叠加范围。

产物达到目标等级时，仍先按产物的虚拟占位计算并结算爆炸，再交付产物。爆炸不额外扣步；周围材料不会因挡物消失而自动滑动。木箱不是通关目标，可以残留。获胜仍要求合成材料全部交付、每条链目标数量准确完成。

**这是对用户爆炸建议的首版收敛：保留“参与合成→炸掉旁边方块”，把受损对象限定为有清晰外观的易碎木箱。** 普通苹果不暗中获得护盾，也不临时依赖算法决定炸不炸。游戏帮助明确写“炸开四周木箱，材料不会受损”。如果未来要炸毁普通材料，必须单独设计废料标记、质量损失和目标规则，本版不混入这种模式。

### 4.2 “当前有 5 个苹果”怎么处理

在五个苹果中随机给一个附加爆破能力，**不额外生成第六个苹果，也不替换成万能牌**。这样随机性不改变本关材料总量。五个苹果并不自动等于一套合法材料：现有规则必须清空材料，单独五个苹果不能全都两两合成桃子。

第 16 关将这个想法具体化：`苹果×5 + 橘子×2 → 桃子×3`。两颗橘子先得到第六个苹果；其中一个开局苹果带爆破能力，用其合成去清路。基础质量为 `5×4 + 2×2 = 3×8 = 24`。这只证明配料正确，空间布局仍必须另外验证。

首发第 15 关固定标记，避免教学随机；第 16、18、23、24、28、30 关允许从人工制作且已完整验关的 2–3 个变体中选一个。第 17、19 关固定标记。每个变体写死标记牌 ID，不能从所有苹果中临场盲抽。若只有一个变体通过验证，就只发布一个，不为“随机”降低验关标准。

采用**开局可见的随机变体**，不是玩家快失败时突然发卡。高难度由关卡编排标注，不在后台猜测玩家能力。中途救援发卡留作后续实验，因为它会影响剩余步数、解题公平性和回放。

### 4.3 预览与出题

选中爆破牌后，方向预览同时显示：滑动路线、合成产物、爆心、受影响木箱、清除后的占位轮廓。普通移动不会显示即将爆炸的假反馈。

第 15 关只安排一个明显受益的爆点；第 17 关引导先把横块移出新通道；第 19 关让玩家意识到木箱既挡路也能停靠，提前炸掉可能增加步数，但不能导致不可恢复的空间死局。

## 5. 第 20 关：一次性停靠花台

花台是带花纹的地面区域，不是一张材料牌。它只有一次停靠次数；材料滑动时若完整对齐一个尺寸相同、尚未使用的花台，便提前停在花台上。花台立刻变为普通地面，本次滑动结束，总共只计一步。

规则边界：

1. 花台按材料矩形左上角与区域左上角一致、宽高完全一致判断；仅擦过或部分覆盖不触发。
2. 大小不匹配的材料正常经过，花台不消耗。2×1 花台不会停住 1×1 苹果，也不会旋转接住 1×2 树苗。
3. 当前操作从花台上出发，不因起始占位触发；必须实际移动进入。
4. 候选占位先做墙、障碍和材料碰撞检查。遇到合法同类时按正常合成处理，不能穿过对方去触发其脚下花台。
5. 花台只响应进入空位的滑动；合成产物生成其上不会消耗花台。放置或挪动障碍也不会触发它。
6. 仍有材料或障碍占据花台时，按普通占位阻挡处理。花台与木箱、固定石块、传送门在关卡定义中不得重叠；不提供在花台上开局放障碍的选项。
7. 多花台时先触发沿路线遇到的第一个匹配花台；不增加开关按钮。

它解决“一滑就过头”的问题，但停点用完就消失。第 20 关用 1×1 花台教学，第 22 关再用 2×1 花台；第 24 关让玩家决定把停点留给哪条链。所有花台都可见，不靠记住隐藏触发次数。

## 6. 第 25 关：成对传送门

一对门有同一符号和颜色，两个端点都是地面区域；每对门全关共享 **一次**使用次数。材料滑入与自己尺寸一致的空入口时，若出口完整空闲，就出现在另一端对应区域，并立刻结束本次滑动，总计一步。使用后两端同时变成普通地面。

具体约定：

- 双向通行，入口与出口可互换；尺寸固定，材料不旋转、不升级。1×1、2×1、1×2、2×2 的门都使用相同的“完整匹配”规则，但正式关卡只使用设计表中列出的尺寸。
- 出口空闲判定按当前移动牌已离开原位置后的占位计算。出口不得与其他材料、石块、木箱或可挪障碍重叠；大块所有格都要检查。
- 出口被占时，入口作为普通地面，材料可正常通过，不消耗次数。界面预先显示“出口被占”，不能等触发后才揭晓。
- 不匹配尺寸的材料正常经过；起步时已经站在门上不触发，需要再次移动进入。
- 正常碰撞优先；入口有同类材料时先合成，产物不自动传送。传送到出口后不追加合成，也不在同一步触发其他地形。
- 每个定义中的地形区域互不重叠；允许两个端点相邻。每次穿行立即结束动作并消耗共享次数，不产生循环。每关至多一对门。
- 门是帮助改变路线的资源，不能是消耗错了就永远分隔材料的唯一桥梁；否则无法满足空间无死局的发布要求。

第 25 关只用 1×1 门和单链；第 26 关引入先让开出口；第 27 关验证横块通行；第 28、29 关分别与爆破、花台组合。第 30 关才同时出现三种新机制，且每种最多一个。

## 7. 一个动作如何结算

所有规则由纯逻辑引擎计算；表现只消费事件。拖动预览、实际提交、提示和离线验关共用同一转移函数。

```text
校验 revision、阶段、方向、剩余步数
  → 逐格扫掠整个矩形
  → 墙/障碍/材料碰撞；允许时完成正常合成
  → 若候选位置为空：检查匹配花台或可用传送门
  → 得到完整、确定的动作结果
  → 有效操作扣 1 步（布置除外）
  → 更新移动/合成结果
  → 若本次合成带爆破：清除爆区木箱并消耗标记
  → 本次达到目标的产物交付
  → 更新一次合成积分、连击及地形次数
  → 先判胜，再判步数耗尽
  → 原子保存 before/after 和事件
```

障碍挪动仍一次一格；不触发花台、传送或爆破。无效动作不改变任何消耗、随机状态和分数。一次滑动最多发生一次合成、一次爆破；花台停靠和传送是另一种移动终点，不能在同一动作中连续触发。

新事件建议为 `blast-resolved`（爆区、移除 ID）、`brake-consumed`（花台 ID、停点）、`portal-used`（门 ID、两端位置）。现有移动、合成、交付、关卡结束事件保留。逻辑先完整提交，再播放短动画；撤销、重开或新输入使旧动画失效，不允许动画回调二次修改棋盘。

```js
  // 保留 rows/cols/mask/rocks/tiles/chainGoals/footprintByChain/obstacle

    crates: [{ id: 'crate-1', row: 2, col: 2 }],
    brakes: [{ id: 'brake-1', row: 3, col: 1, width: 2, height: 1, charges: 1 }],
    portals: [{
      id: 'portal-1', width: 1, height: 2, charges: 1,
      a: { row: 0, col: 0 }, b: { row: 2, col: 4 }
    }]
  },
  variants: [{
    id: 'v1', bombTileIds: ['fruit-a']
    // 每个变体另配 referenceSolution、scoreProofs
  }]
}
```

`variants` 首版只允许切换爆破标记牌，不修改坐标、目标或步数。没有随机性的关卡也规范为一个默认变体。实际加载时先解析变体成完整定义，再校验和建立状态；坐标、ID、材料守恒、尺寸、地形重叠和全部开局障碍摆法均须合法。

动态状态至少新增：每张牌剩余能力、存活木箱集合、花台剩余次数、门剩余次数、`variantId`。`definitionHash` 必须包括规则、评分、目标、全部坐标、尺寸、能力、变体、地形配置和星级阈值，不能沿用只覆盖旧字段的哈希。

### 8.3 不能沿用的旧验关假设

当前 `tools/validate_v06_levels.cjs` 的紧凑状态编码只记录牌面和障碍，并从材料推算交付；其评分检查使用“牌数减少”识别合成。v0.7 必须改成明确的材料集合、交付状态和 `merge` 事件计数，不能让炸掉木箱被误算成合成。

空间状态键必须包含：关卡/变体身份、材料位置/类型/能力、已交付数、障碍位置及剩余额度、木箱存活、花台和门的剩余次数。相同位置的爆破苹果与普通苹果不是同一状态。枚举时可忽略材料 ID，但回放需保留或重建 ID 对应；地形 ID 需要稳定。

预算搜索另外保留总剩余步数，或使用“相同完整空间状态以较少已用步数支配较多已用步数”的剪枝。若搜索最高分/三星，还必须保留连击、挪位计数和积分状态，不能把通关搜索的去重直接用于评分证明。

### 8.4 随机、公平和恢复

关卡首次进入时在已验证变体中等概率选一个，写入该关的 `variantId`；同一存档内重试、撤销、刷新和重复进入均不换变体。不同玩家可能抽到不同变体。教学关 15、20、25 固定，不随机。客户端实现无需在线随机服务，也无需在每一步调用随机数。

变体必须在开局显示爆破标记；参考解和三星门槛覆盖所有可发布变体。正式版采用同关统一星级分数阈值，但每个变体都必须有真实三星回放；变体间推荐解步数差超过 2 步时回炉，不靠随机难度强迫重开。

存档命名空间使用 `tile-explorer.slide.v07.*`，预览与正式隔离。保存关卡 ID、解析后的定义哈希、变体 ID、动作日志、最佳记录和解锁进度；三种地形状态由同一引擎回放恢复。撤销整个动作，同时还原木箱、能力、门/花台次数、步数、积分和交付，不只还原材料位置。

v0.6 仅迁移声音、减少动态效果等偏好；旧成绩和动作不伪装成 v0.7 成绩。将来若给相同布局做成绩迁移，必须另建明确映射并验证。定义哈希改变时安全重开该关并解释“关卡已更新”；成绩按版本隔离。存储不可用时维持内存游玩，并提示本次进度可能无法保留。

## 9. 可解性：三个不同的保证

**配料正确、开局有解、所有空间局面有解是三个不同命题。** v0.7 正式发布同时检查它们；有限步数耗尽仍是正常失败条件。

### 9.1 材料守恒

每条链独立计算：等级 `t` 的材料质量为 `2^t`，初始质量必须等于目标数量乘目标等级质量。运行中：

```text
场上剩余材料质量 + 已交付目标质量 = 初始质量
```

爆破能力不增加质量；木箱/花台/门不是材料；所有普通材料免受爆炸伤害。尺寸与质量无关，2×2 荔枝仍只是一份荔枝。初始材料必须低于该链的目标等级，不把现成目标直接摆上去。第 16 关的五苹果方案按此检查。

### 9.2 开局预算内可解

对**每个可选变体 × 每个允许的障碍放置点**分别跑真实引擎。至少一条完整路线必须在 20 步内获胜，并保存逐步回放；另外保存至少一条满足该关三星阈值的预算内路线。

定义 `shortestMoves` 时必须使用 BFS/一致代价搜索等可证明最优的方法。现有偏向升级的提示搜索找到的是可行路线，不应自动标记为最短解。设计稿中的步数区间只用于筛选目标。

### 9.3 无不可恢复空间死局

从所有合法开局枚举可达空间图，暂时忽略总步数，**保留**障碍移动额度、爆破标记、木箱、花台和门次数。每一条边都调用发布引擎的实际转移。对全部获胜节点做反向遍历；必须覆盖所有可达节点，否则输出最短反例动作序列并拒绝该布局。

这保证用错门或提前爆破之后，棋盘仍存在未来完成的路径；不保证玩家已经浪费了 18 步后还能在剩余 2 步通关。界面分别说明“步数用完”和“暂未找到提示”，不能把搜索超时说成死局，也不能承诺无论怎么滑都能过关。

全图证明可能很昂贵。先缩小棋盘、减少材料/地形、减少随机变体；利用可靠的对称归一化与紧凑编码。到达资源上限返回 `unverified`，阻止发布，不能用抽样游玩或一条参考路线代替完整证明。

验关报告应逐关列出：规则/定义哈希、变体、放置点、节点/边数量、未覆盖节点数、最短步数、参考解、三星回放、能力实际使用情况、耗时与证明是否完成。第 15、20、25 关必须检查参考解确实展示新机制；其他关卡的必需/可选角色见设计稿。

### 9.4 提示与失败恢复

在线提示只在剩余步数内找一条可行解；首选后台 Worker，给出约 1.5 秒的初始搜索预算，超时返回“暂未找到路线，可撤销或重试”。低性能设备允许分片继续，但不得卡住输入。

请求绑定 `levelId + definitionHash + variantId + revision + sessionEpoch`；撤销、重开、换关后取消旧结果。已验证参考解只用于与当前状态确实匹配的前缀，不能从中间任意套用。算法若只能证明预算不足，应建议撤销，而不是临时增添炸弹。

## 10. 界面、评分与体验验收

目标栏继续展示合成路径、剩余目标和 20 步预算。只在有对应元素的关卡显示一个简短机制说明；不增加常驻的道具商店或一排新按钮。爆破用角标、花台用花纹、传送门用同符号配对，颜色只是辅助。

首次教学文案：

- 15：“带炸弹的材料参与合成，会炸开四周木箱。”
- 20：“滑进同样大小的花台，会停一次。停过就变成普通地面。”
- 25：“滑进入口，会从另一端出来。出口要空着，这对门只能用一次。”

教程使用不改状态的虚影，可点选重看；真实操作开始即退场。方向预览显示最终结果，门的路线分为入口段与出口落点，不画穿越中间障碍的普通滑行线。声音关闭、减少动态效果开启时，所有消耗仍有静态标记和文字反馈。

评分沿用 v0.6 的合成奖励、连击和效率奖励；爆破清掉多个木箱只播放一个反馈，不计多个合成。花台停靠、传送属于一次挪位；连续两次挪位会按现有规则断连击。所有分数/连击随动作撤销。30 关各 1–3 星，共 90 星；阈值在布局验证后根据真实回放配置，设计阶段不虚构可达分数。

难度试玩至少招募 8–12 名未参与开发的玩家，分段体验避免一次 30 关的疲劳偏差。记录首过率、有效步数、撤销/提示使用、错误预测和关卡耗时。教学关目标首过率 ≥85%，基础练习约 65–85%，章节挑战约 40–60%；这些是调优目标，不是统计结论。小样本用于发现问题，不声称代表全部玩家。

第 15/20/25 关体验成功的标准，是玩家能在操作前说明将发生什么。若玩家只反复试错，应先调整摆法和预览；第 30 关再追求“组合用起来很顺”的完整体验。
