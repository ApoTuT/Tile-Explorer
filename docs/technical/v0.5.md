# v0.5 技术方案与实施：一滑到底，碰撞合成

更新日期：2026-10-23。当前规则为 **`slide-v05-2`**，替代早先的一格移动规则。用户明确要求：划动一次就沿该方向滑到头。

旧的单格方案与当时的验收记录移至 [历史单格方案](v0.5-one-cell-history.md)，只作为历史资料，不代表当前玩法。[初始布局研究](v0.5-layout-study.json) 同样仅属于单格规则。当前证据以 [实际内核报告](v0.5-level-report.json) 和下文为准。

## 1. 当前规则

玩家在一块方块上向上下左右划动，选中的这一块沿直线持续滑行：

| 前方情况 | 行为 |
|---|---|
| 空格 | 继续前进，不在中途空格停下 |
| 棋盘边界 | 停在边界内的最后一个格子 |
| 不同图案 | 停在它前面的最后一个空格；如果紧邻则无法移动 |
| 相同基础图案 | 到达该格并合成，消耗两块，成品自动收集 |

一滑只操作选中的一块，不推动整排，不穿过障碍，不按手指划动长度决定落点。短划与长划只要达到识别距离，终点完全相同。键盘方向键遵守相同规则。

一次滑动最多完成一次合成。碰到第一张同类就结束该动作，成品不留在棋盘，也不会继续滑动触发第二次合成。静止相邻的同类不会自动消除，仍需主动朝对方划动。

一整段成功滑行只计一次操作、写一个撤销事务和一条存档动作。未移动的边缘或紧邻异类阻挡不计操作。无倒计时、步数限制或最优步数惩罚。

首轮继续使用草莓、汽车、树苗三条二合一配方，材料数量精确匹配目标。目标全部完成且棋盘为空才通关。

## 2. 内核与路线数据

`engine.inspectAction` 从源位置沿整数方向逐格扫描，收集所有经过的格子，遇到边界或第一块牌时结束。规则结果包含：

```js
{
  ok: true,
  kind: 'move', // 或 merge
  sourceId: 'c1',
  from: {row: 0, col: 1},
  to: {row: 1, col: 1},
  path: [{row: 1, col: 1}],
  distance: 1,
  stoppedBy: 'tile',
  blockerId: 't1'
}
```

合成结果额外包含 `targetId`、`recipeId`、`resultId`。`path` 包含终点，合成时包含碰撞格，不包含源格或阻挡的异类格。它同时用于预览、指引、动画与验证；不能由视图另算一套落点。

`applyAction` 仍一次性提交规则状态。滑到空格时移动源实体；合成时立即移除双方、增加对应目标计数。事件记录完整 `from/to/path/distance`，不依赖屏幕坐标、时间或动画完成回调。

纯规则、会话、输入、表现继续分离，不引入物理引擎。现有 `grid.js`、`solver.js` 和共享配方注册表继续复用，只有合法动作的含义改变。

## 3. 输入与反馈

保留单主指针、8 CSS px 方向识别、1.35 倍轴锁定，以及 `clamp(格子宽 × 0.18, 12, 24)` CSS px 的释放阈值。释放时重新采样坐标；回到起点附近或越过起点反向划动会取消。

手指只表达方向，源方块按手势做少量跟随反馈；整条可走路线均点亮，并突出最终落点。不能让玩家误以为拖到某个中间空格便可以停下。

普通滑动使用与距离相关的过渡：`min(300, 100 + max(1, distance) × 50)` ms。合成表现先让基础方块从源格滑向碰撞格，再成长、收集，避免隔空变成成品。碰撞双方的残影和成品均不拦输入。

状态与目标立即提交，表现可被新操作、撤销、重开、弹窗或切关取消。下一次手势使用最新稳定状态，不等待整段收集动画。减少动态效果关闭非必要位移，保留路线和终点信息。

教学虚影也沿完整路线移动，不再示范半格或单格。所有帮助、标题、读屏与键盘文案统一为“一滑到底”。

## 4. 三关与参考解

下文坐标从第 1 行、第 1 列起算。`S/C/T` 分别为草莓、汽车、树苗，`.` 是空格。实际游戏显示原有 SVG 图形。

### 第一关：一滑，就碰到了

```text
S . S
. . .
```

把 `(1,1)` 草莓向右划一下，穿过空格，直接撞到 `(1,3)` 的草莓并合成。**一滑通关**，不需要划两次。

### 第二关：让个位置

```text
S C S
C . .
```

1. 上方汽车向下滑到下边缘，空出草莓通道。
2. 左上草莓向右滑到底，合成大草莓。
3. 下排任一汽车朝另一辆滑动，合成跑车。

也可以先合成下排汽车，再处理草莓。让路后的同类相邻共存，不会在第一次划动后自动消除。

### 第三关：往哪边挪，更顺手

```text
S C S
C T .
T . .
```

五次参考滑动：

1. 中心树苗向下滑到下边缘。
2. 上方汽车向下滑，被树苗挡住，停在中心格。
3. 左上草莓向右跨过空格合成。
4. 中心汽车向左与左侧汽车合成。
5. 下排中心树苗向左与另一棵树苗合成。

本关发现的是“**其他方块也可以成为停靠点**”，树苗先帮汽车停在合适位置，最后再合成。中心树苗先向右的路线也能通关，最快 6 次；不要求玩家一开始算出最优解。

六次备选：中心树苗右、左侧汽车右、上方汽车下、左上草莓右、右侧树苗下、该树苗左。

## 6. 会话、撤销和旧存档

当前规则身份从 `slide-v05-1` 升为 `slide-v05-2`，存档前缀仍为 `tile-explorer.slide.v05.`，预览追加 `preview.`。规则身份与布局哈希改变后：

- 旧单格动作日志不在新规则下回放，当前关安全重开，并说明“一滑到底”已更新。
- 旧关卡完成记录不当作新规则成绩；音效和减少动态效果设置保留。
- 新手能力按新规则重新学习。第一关直接展示跨空格合成，不再要求先完成一个空格移动。
- 同一新版规则下的滑行、合成、目标和完整撤销均可保存恢复。

300 次合法往返之后，一次跨空格合成得到总计 301 个事务；刷新后可以完整撤销 301 次。技术存储大小限制与内存降级保持，不增加玩家步数上限。
