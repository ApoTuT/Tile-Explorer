# v0.4 技术方案：多图形、前三关打磨与情境指引

日期：2026-10-22。工作名：**叠出新花样**。

状态：**设计方案，尚未实现、验收或部署**。本文以当前 v0.3 实现 `9a16b4c` 为接入基线；文中的数据结构、素材、布局和指标是实施约定或待验证候选，不是已有功能。正式名称与美术细节可继续调整。

## 1 版本目标与交付范围

让第一次进入游戏的玩家，在前三关逐步学会“找同类、拖过去、先暂放再接回来”，并愿意看看下一种合成结果。

| 本轮工作 | 具体交付 |
|---|---|
| 丰富图形 | 水果、交通、植物三条合成关系，共六张基础／成品图形；用同一份内容注册表扩展 |
| 打磨前三关 | 单种图形学拖动、两种图形学借位、三种图形独立组合；完整重新验关 |
| 通用名称 | 游戏标题、目标栏、暂放位、提示、选关、结果、读屏名称和键盘说明一起调整 |
| 游戏化界面 | 紧凑顶栏、横向目标栏、中央大牌阵、一个暂放位、底部工具；参考用户截图的层级与厚牌触感 |
| 两类指引 | 首次按动作教学；操作过程中解释具体落点、遮挡与暂放状态 |
| 持续顺滑 | 保留按帧跟手、释放点重采样、节点复用、可打断表现和完整撤销 |
| 可交付 H5 | 本机及服务器子路径都能运行，内容、存档、素材与发布版本有明确边界 |

本轮仍为三关，不扩成 50 关。多级升级链、碰撞物理、任意摆牌、金币商店和广告机制不进入本轮规则。水果、交通、植物之后可以继续加入建筑、食物、玩具、手作、天气等内容，不在前三关同时堆入所有类别。

## 2 内容与统一规则

### 2.1 首发合成关系

| 类别 | family | 两张相同基础牌 | 成品 resultId | 成品变化与反馈 |
|---|---|---|---|---|
| 水果 | strawberry | 小草莓 | strawberry-large／大草莓 | 果肉鼓起、叶片轻抖；大小变化一眼可见 |
| 交通 | car | 普通小车 | sports-car／跑车 | 车身变流线、尾翼弹出、车灯短亮 |
| 植物 | tree | 小树苗 | tree-grown／大树 | 树冠展开、枝叶舒展 |

水果表达“变大”，交通表达“升级”，植物表达“生长”。车辆的档次用造型表达，不引入价格计算。六张素材必须有共同画风，成品与材料应有明显轮廓或结构差异，不能仅换颜色。

`category` 只用于内容组织。合成依据是具体 `family + stage`，不是“同属水果就能合成”。例如未来增加苹果，也不能与草莓混合。

### 2.2 玩家动作

1. 只有无遮挡的上层基础牌，或暂放位内的基础牌，能够作为拖动源。
2. 拖到相同 family、相同基础阶段的下层牌上，且目标不再被其他牌遮挡，松手后合成。
3. 源牌和目标牌一起消耗；成品立即计入对应目标，再播放升级、飞入目标栏的表现。
4. 成品不留在棋盘，不接受再次拖动或合成。每关只采用一段合成关系。
5. 暂放位只能放一张上层牌。暂放解除这张牌的遮挡；暂放牌只能通过合法配对取回。
6. 不允许暂放位交换、不允许把牌随意摆在空白处、不允许下层牌单独拿走。
7. 拖动经过目标不结算；不限制路径方向、不计算途中碰撞。牌阵用位置关系自然引导斜拖。
8. 无效松手回位，不计操作、不改材料或目标、不写入操作历史。
9. 借位和合成都各计一次有效操作，无倒计时或操作次数上限。撤销恢复整次事务。

同类部分错位的上下叠放可以存在；已经完全对齐、且满足条件的一对必须自动结算，不能留下等待点击的假稳定状态。官方初始牌阵应排除可立即自动结算的配对。

## 3 前三关候选

保留 100×100 世界单位的牌面、两层结构和一个固定暂放位。第二、三关底牌间隙先沿用 6 世界单位；视觉厚度和阴影不参与碰撞或遮挡计算。

以下是可直接进入实现与验关的候选，不是最终验收布局。一、二、三关表示学习递进，不强制总操作数恰好为一、二、三次，也不要求玩家采用唯一顺序。

### 3.1 第一关：拖过去，变大啦

目标：大草莓 × 1。只教拿起、拖动、同类对齐和自动交付。

| ID | x | y | 层／图形 |
|---|---:|---:|---|
| u1 | 40 | 40 | 上层／小草莓 |
| l1 | 105 | 80 | 下层／小草莓 |
| 暂放位 | 235 | 80 | 独立容器，容量 1 |

参考动作：`u1 → l1`。暂放位保留可用，但不抢先教学；玩家如果主动先暂放，指引应改为提示从暂放位配对，不要求重开。

画面以两张大牌和短虚影轨迹为重点。成功后让成品飞入目标栏，建立“配对之后会发生什么”的联系。

### 3.2 第二关：先借个位

目标：大草莓 × 1、跑车 × 1。两张上层共同遮住两张底牌，开局需要借位。

| ID | x | y | 层／图形 |
|---|---:|---:|---|
| l0 | 0 | 160 | 下层／普通小车 |
| l1 | 106 | 160 | 下层／小草莓 |
| u1 | 53 | 80 | 上层／小草莓 |
| u2 | 53 | 240 | 上层／普通小车 |
| 暂放位 | 230 | 160 | 独立容器，容量 1 |

参考动作：暂放 `u1` → `u2 → l0` → 暂放位内 `u1 → l1`。

也允许先暂放 `u2`，再完成草莓、接回小车。教程根据实际暂放的是哪张牌选择下一步，不能用固定脚本强迫草莓先走。

### 3.3 第三关：试着自己来

目标：大草莓 × 2、跑车 × 1、大树 × 1。共八张材料，四次合成；加入植物，并组合直接配对与借位。

| ID | x | y | 层／图形 |
|---|---:|---:|---|
| l0 | 318 | 160 | 下层／小树苗 |
| l1 | 212 | 160 | 下层／小草莓 |
| l2 | 0 | 160 | 下层／小草莓 |
| l3 | 106 | 160 | 下层／普通小车 |
| u1 | 218 | 80 | 上层／小草莓 |
| u2 | 53 | 80 | 上层／小草莓 |
| u3 | 53 | 240 | 上层／普通小车 |
| u4 | 218 | 240 | 上层／小树苗 |
| 暂放位 | 318 | 270 | 独立容器，容量 1 |

一条候选路线：`u4 → l0`（树）→ `u1 → l1`（草莓）→ 暂放 `u2` → `u3 → l3`（车）→ 暂放位内 `u2 → l2`（草莓）。

这套图形分配经临时模型推演可作为候选；它尚未经过 v0.4 实际内核、素材辨识区域、目标计数和存档回放的联合验证，不登记为“关卡已通过”。默认不播放手把手演示，玩家求助或出现重复无效操作时才给当前一步建议。

### 3.4 可解性是发布条件

多图形会限制每张上层牌的可用目标，单个暂放位也可能被不合适的图形占住。不能把原布局任意换色后直接上线。

- 每个 family 单独检查：上层材料数 = 下层材料数 = 对应成品目标数。仅检查总张数为偶数不够。
- 核对同层不重叠、暂放位不遮牌、初始稳定、实际图案露出和参考路线。
- 用实际 v0.4 内核完整枚举每个合法可达状态，要求每个状态都存在通关路径，且无需撤销或重开。
- 发现不可恢复状态时调整图形分配或几何关系，不能用教程禁用合法动作来掩盖问题。
- 预算耗尽属于“尚未验证”，不能计入通过；保留失败状态和复现动作，便于修订。

v0.3 的 `3 / 8 / 74` 状态及无死局结论不能继承为 v0.4 的证据。

## 4 界面结构与命名

参考用户提供的第六关截图：暖黄底色、紧凑顶栏、横向槽、占主要面积的厚白牌、底部大工具按钮。参考其画面层级与触感；本项目上方承担的是成品目标，不是七格三消暂存槽。

| 区域 | v0.4 设计要求 |
|---|---|
| 顶栏 | 返回／选关、第几关、设置；主游戏内缩小品牌标题 |
| 目标栏 | “本关目标”及成品图标、各自完成数量；三种成品按配置稳定排序，完成后点亮和打勾 |
| 中央牌阵 | 页面主要空间；减少外层网页卡片和装饰留白，底牌紧凑，上层保留足够错位 |
| 暂放位 | 牌阵旁固定一格，以空框及“暂放一张”表达容量；位置不随材料减少而移动 |
| 状态提示 | 一次一条短提示，放在牌阵边缘，不遮挡源牌、落点或暂放位 |
| 底部工具 | 撤销、重开、帮助；图标配简短文字，音效和减少动态效果放入设置 |
| 通关 | 收齐后短反馈及下一关按钮，保留撤销；末关可重新选关 |

替换范围包含 HTML title、meta、页面正文、选关说明、结果提示、错误反馈、设置／帮助、ARIA 标签、键盘说明、noscript 和素材替代文字。固定功能文案集中到 `copy.js`，物品名称来自 `content.js`。源码兼容路径或历史文档中的 v0.3 名称不属于玩家可见文案泄漏。

### 4.2 视觉与响应式

- 使用暖黄背景、白色圆角厚牌、清楚侧边和克制投影；背景装饰退到边缘，牌面图形饱满且有轮廓。
- 图形不能只靠颜色区分；基础与成品需要形态变化，目标图标与实际成品使用相同资源。
- CSS 主题变量集中定义背景、牌面、边框、阴影、成功／不可落下状态、字体与间距。
- 手机以 `100dvh` 为主并提供 `100vh` 回退，使用紧凑纵向分区，工具栏考虑安全区。菜单内容可滚动，实际拖牌区域避免依赖页面滚动。
- 移动端按钮和可拖牌的实际触控尺寸至少 44 CSS 像素；检查 320×568、375×667、390×844、768×1024、1280×1000。
- 当前 View 最大缩放写死为 `.84`，使牌面最多 84 CSS 像素。v0.4 改为按关卡初始边界和可用空间适配，牌少时允许放大集中；上下限需实图验收。
- 一关开始时确定牌阵与暂放位的统一变换。消耗材料不重新居中或放大剩余牌；真正 resize、方向变化才重新布局，并取消进行中的手势。

## 5 指引设计与状态机

### 5.1 两种职责

**新手指引**在首次学习时教一个动作；**操作指引**解释当前手势和落点。均不得修改规则状态、代替提交或禁止另一条合法路线。

新增 `TutorialController` 与 `GuideView`：前者读取稳定状态和语义事件决定提示，后者只绘制虚影、路径、边框和短文字。演示层 `pointer-events: none`，不改变真实牌的位置或焦点。

### 5.2 关卡教学状态

| 场景 | 状态与反馈 | 完成依据 |
|---|---|---|
| 第一关尚未配对 | 展示一条同类拖动虚影；抓牌时立即隐藏 | 实际成功提交合成，标记 mergePair |
| 第一关玩家先暂放 | 改为展示暂放牌到可用同类的关系 | 暂放牌实际合成，不锁在原预设轨迹 |
| 第二关需要借位 | 突出暂放位及可拿起的源牌 | 实际 park 提交，标记 parkTile |
| 第二关已经暂放 | 指出另一张上层牌及其当前合法目标 | 实际场上配对，重新计算下一步 |
| 第二关可以接回 | 暂放牌及对应底牌轻亮 | 暂放牌实际合成，标记 retrieveTile |
| 第三关 | 默认无手势演示，允许独立观察 | 求助时只给当前一步，不展示整条答案 |

键盘完成同一逻辑动作也可标记能力学会；之后若发生“只点不拖”，仍可给一次对应输入方式的简短提醒。减少动态效果时使用静态箭头和边框，不能失去教学信息。

### 5.3 输入与反馈事件

输入模块保留规则校验，同时新增只读语义出口：`gesture-start`、`drag-start`、`tap-without-drag`、`drop-rejected`、`gesture-cancelled`。成功依据必须来自 Session 的 `move-committed` 及其完整结果事件，不能根据动画结束判断学会。

| 情况 | 反馈 | 状态影响 |
|---|---|---|
| 首次只点不拖 | “按住，拖到同类上”，短展示拖动方向 | 无 |
| 接近合法同类 | 目标边框／吸附预览及可落下标记，松手后轻落下 | 松手验过才提交 |
| 不同图形 | “找相同图案配对”，轻量拒绝反馈 | 无 |
| 目标仍被挡 | 晃动实际挡牌，提示“还有方块挡着” | 无 |
| 暂放位已满 | 突出占用牌，提示先接回来配对 | 无 |
| 空白松手 | 平滑回位，通常不追加文字 | 无 |
| 成功 | 合成表现和正确目标组点亮优先 | 一次完整事务 |

反馈优先级：真实成功／失败反馈 > 当前主动手势 > 显式求助 > 闲置演示。新反馈替换旧提示，不叠加多段文字或多个动画小手。

### 5.4 提示节奏与取消

- 首次教学短演示一轮，留出玩家尝试时间；起始调参可用约 1.2 秒演示、至少 4 秒间隔。以同一局的同一教学阶段为单位最多两轮，点击、拒绝或其他事件不能反复重置次数。具体节奏属于试玩调参，不是规则。
- 第三关不因玩家安静观察就自动泄露答案；点击帮助，或短时间内连续两次同类无效操作后，才给一步提醒。
- 建议动作从当前合法动作中选择；优先直接配对或接回可配对的暂放牌，确实需要借位时才突出暂放位。动作需能继续通关。
- 提示计算仅在稳定状态变化或求助时运行，不放进 pointermove 或逐帧动画；缓存绑定当前局面。预算不足时只显示一般操作帮助，不伪造“正确下一步”。
- 每次重开、撤销、切关、恢复、打开弹窗、resize、scroll 或页面隐藏，取消旧虚影和计时器。校验 `runToken + levelId + revision`，不能只依赖可能被撤销恢复的 revision。
- 已学会的能力不在重开时反复教学；帮助可随时重看，重看不清除关卡进度。教程记录与游戏事务分开保存，撤销不删除已经掌握的能力。
- 教程首次自动、实际操作即退场；“？”重看。帮助／设置弹窗打开时禁止棋盘与快捷撤销穿透，关闭后恢复合理焦点。

## 6 技术结构与现有接入点

沿用原生 JavaScript、DOM 方块与 CSS／Web Animations 的轻量结构。当前是八张材料以内的离散拖放，新增引擎不是本次目标；继续将纯规则、稳定会话、输入、视图、表现与存储分开。

~~~mermaid
flowchart LR
    C[content 配方与素材标识] --> E[engine 纯规则]
    I[input 指针与键盘] --> A[app 协调]
    A --> S[session 状态与历史]
    S --> E
    S --> D[storage 合法回放]
    S --> V[view 节点与目标栏]
    A --> P[presentation 可取消表现]
    I --> T[tutorial 只读教学判断]
    S --> T
    T --> G[GuideView 虚影与提示]
~~~

| 模块／当前位置 | 计划改动 |
|---|---|
| 新增 `web/merge-v03/content.js` | family、基础／成品定义、配方、素材 ID、识别区域、反馈配置与内容版本 |
| 新增 `web/merge-v03/copy.js` | 通用界面文案及依据物品名称组合的提示，避免散落动物词汇 |
| `engine.js` | 取消 dog／young／golden 限制；多目标计数、材料配平、配方解析、哈希与求解键 |
| `levels.js` | 三关新图形分配、目标与候选布局；提供教学配置，不包含可执行 UI 脚本 |
| `session.js` | 继续唯一持有稳定状态和完整历史；提交后通知教程，旧表现不回写状态 |
| `view.js` | 按内容渲染素材和读屏名称，目标按成品 ID 复用，响应式缩放；替换写死的首关箭头 |
| `input.js` | 保留手感与规则复核；统一 `.merge-tile` 命名，输出教学语义事件及准确拒绝原因 |
| `presentation.js` | 根据事件显示正确基础／成品，选择反馈预设并飞向对应目标组 |
| 新增 `tutorial.js`／`guide-view.js` | 教程状态、学习记录、一步提示及纯表现层；与规则历史隔离 |
| `app.js` | 连接上述模块，处理完整事件批次、目标定位、弹窗、焦点和取消生命周期 |
| `storage.js` | 新前缀、内容哈希、回放长度验证与教程记录，保留旧版数据 |
| HTML／CSS | 页面布局、工作名、通用文案、设置／帮助弹窗与主题变量 |
| 资源清单／导出／QA | 更新统一清单、内容引用验证、测试与浏览器脚本，输出 v0.4 证据 |

现有 `web/merge-v03/`、`merge-v03.html`、`config/merge-v03.json` 和导出脚本名可作为兼容路径继续承载迭代，避免复制一套 v0.4 运行时。玩家可见版本由内容元数据和界面控制。文件加载顺序与服务白名单仍由唯一清单管理，不能另维护一份散落的资源列表。

原九关的 Python 规则、旅行成绩与小剧场保持独立。v0.3 单物种测试需要改写为新版等价规则测试；原版快照保留在 Git 和服务器发布备份，不能把新规则伪装成旧规则兼容回放。

const content = {

示例识别区域只是字段说明，必须依据最终素材重新确定。注册表还需补齐 car、tree 及其对应物品、配方与素材；缺引用、重复 ID、未知阶段或多个歧义配方均应在启动／导出检查时失败。

`assetPaths` 是图像／内容音效 ID 到 web 根目录下规范相对路径的唯一映射。View、Presentation 和 Audio profiles 共同通过资源解析器取得相对 URL，不再各自拼文件名。导出遍历物品、配方反馈与 UI 的全部资源引用，验证映射有定义、文件存在且全部进入共享清单；路径仍禁止外部 URL、父目录和查询参数。

### 7.1 稳定状态

~~~javascript
{
  levelId, ruleset, definitionHash,
  tiles, goals,
  delivered: {'strawberry-large': 0, 'sports-car': 0},
  parkingSlot, parkingId: null,
  successfulMoves: 0, revision: 0, status: 'playing'
}
~~~

`canMerge` 应返回明确 recipeId／resultId 或拒绝原因。提交前检查对应目标尚有需求；消费时增加 `delivered[resultId]`，而不是继续累加 golden。

通关要求每个目标恰好收齐、棋盘材料清空且暂放位为空。未知成品、超额交付、额外材料、每种上下层数量不匹配均为非法内容，不靠通关逻辑容忍。

暂放牌保留材料 ID 和原始牌阵坐标，另由 `parkingId` 标记位置；它不参与牌阵遮挡，视图命中与教程轨迹使用实际暂放位置。所有操作仍经过同一内核与事务撤销。

### 7.2 合成事实与目标定位

~~~javascript
{
  type: 'merge-deliver', sourceId, targetId,
  recipeId, sourceItemId, resultId,
  ordinalWithinResult: 1,
  x, y, revision
}
~~~

View 提供 `goalBox(resultId)`，定位到该成品目标组。界面采用“成品图标＋完成数”的分组形式，组内不使用全局序号寻找 DOM 子节点；ordinalWithinResult 用于该类的反馈和去重核对。

当前 app 使用 `events[0]` 及 `children[ordinal - 1]`，Presentation 固定 puppy→golden，必须一起替换。处理整批事件；若稳定化产生额外交付，所有计数与保存都生效。即使表现取消、资源加载失败或减少动态效果，已经提交的目标也不得丢失或重复。

### 7.3 求解键与内容哈希

求解缓存按剩余材料 ID、暂放材料 ID、排序稳定的完整 delivered 映射建立；同一搜索中固定的牌位置、family 与配方由 definitionHash 约束。所有影响后继合法性的动态字段都必须进入状态键。

新的 gameplay hash 覆盖规则版本、实际配方关系、目标、牌 ID／family／stage／坐标／层级、牌面尺寸和暂放位。按 ID 或键排序后稳定序列化。

标题、语言、音效、美术路径、教程文案和参考答案不进入玩法哈希。现有 hash 没有覆盖配方，却包含 solution；这会导致配方变更未失效、仅修改参考解却重置存档，两点都需要修正。美术和教程另有内容版本，辨识区域变化需重新做可见性验收。

## 8 素材、声音与加载

- 基础交付是三条关系的六张图形及必要 UI 图标。优先沿用项目可维护的本地素材方式，统一视框、中心、占牌比例、描边与透明边距。
- 每类基础图形单独定义关键辨识区域；汽车看轮廓／车窗，树苗看枝叶，水果看果形／叶片。不能继续把所有图形都当成“小狗中央眼鼻区域”。
- 下层牌真实露出比例以至少 50%、关键辨识区域至少 80% 为初始验收门槛，并结合手机截图和陌生玩家判断修订；不能只凭几何比例宣称可辨。
- 图形素材建议放 `web/assets/merge-v04/`，注册表通过 assetId 查资源，图形名称不拼接为任意外部 URL。参考截图不直接裁切为本游戏素材。
- 先提供柔和、短促的通用合成音；水果膨胀、车辆变形、枝叶展开使用不同视觉预设。独立特色音色可在手感验收后追加。
- 复用 AudioManager 的自定义 profiles／相对资源路径能力，使用中性音效 ID，不再在 app 固定 preload／play dog；不改变原九关默认音效路径或设置。
- 新脚本、六张图形及实际使用的声音都必须进入共享清单。校验 HTML 顺序、内容注册表引用、资产存在、服务白名单和静态导出的一致性。
- 拖动继续使用 transform 与 requestAnimationFrame；成长、交付主要使用 transform／opacity。新手势可取消旧表现，不能等特效播完才接受输入。
- 禁止首屏因非必要声音失败而不可操作；图像失败显示具有类型区别的文字／图标占位，仍可继续。发布前资产缺失检查不允许靠占位蒙混通过。

## 9 存档与能力记录

规则版本：`merge-v04-1`。新存储前缀：`tile-explorer.merge.v04.`。

| 存储项 | 内容与边界 |
|---|---|
| session.v1 | 关卡 ID、ruleset、gameplay hash、已提交动作序列；恢复时重新合法回放并重建撤销历史 |
| progress.v1 | 各关当前玩法哈希对应的完成记录 |
| settings.v1 | 音效、减少动态效果等设备偏好 |
| onboarding.v1 | tutorialSchemaVersion 与已学能力 mergePair／parkTile／retrieveTile；不保存真实牌或虚影位置 |

v0.3 的进行中局面和通关记录不能直接解释成新版水果／车辆成绩。保留旧 key，不覆盖旧数据；新版首次从新第一关开始，必要时一次说明“前三关更新啦，来试试新图形”。只迁移经过类型验证的通用偏好，例如原音效开关。

动作长度限制改为基于总目标数 N 的规则上界，不能保留 `goals.golden * 2`。在本轮单格暂放且材料只消耗的规则下，每张上层牌最多借位一次，完成最多 N 次合成，保存序列可使用不超过 2N 的上界；仍需逐步回放验证，不能只看长度。

教程学会记录在成功提交后更新，与会话分开容错。撤销影响棋盘历史，不撤销能力；“重看指引”也不清空成绩。损坏、旧版本、不可访问的存储安全回退；localStorage 不可用时当前游玩保持可用，并简短说明无法保存到设备。

## 10 无障碍与生命周期

- 鼠标按住拖、手指拖和键盘选择源／目标调用同一规则。键盘继续支持 Tab、Enter／空格、Esc、Ctrl／⌘+Z。
- 借位成功后焦点优先落到实际可继续的源牌；通关后可聚焦下一关；普通鼠标拖动不强抢焦点。
- 帮助与设置采用有名称的对话框，纳入统一输入忙碌判断。Esc 关闭／取消，恢复发起按钮或合理的存活控件焦点。
- 每张牌的读屏名称包含图形、层级、是否在暂放位与遮挡状态。目标公告按具体成品说明完成数。
- live region 仅在成功、必要错误或显式帮助时更新，不在每帧／每次 pointermove 播报。
- 可落下／不可落下状态结合边框形态、标记或短文字表达，不只靠红绿颜色。帮助同时提供可读的静态文字／图示，不要求玩家看动画才懂操作。
- 关闭声音、系统减少动态效果或缺失 Web Animations 时，规则、提示和完成反馈仍可理解。
- 统一计算有效动态效果偏好，例如 `systemReduce || userReduce`，供输入回位、拒绝反馈、合成交付和教程共同使用，不能各模块只读自己的开关。切换偏好时取消当前表现并按稳定状态重绘，不回滚已提交操作。
- 后台、pagehide、重开、撤销、选关、弹窗及真正尺寸变化取消输入／演示／表现；旧异步回调不能给新局补交目标或重新覆盖棋盘。

陌生玩家试玩另记三项观察：不解释能否做出第一对；第二关能否理解暂放用途；第三关能否自行识别三种图形完成目标。记录求助、误操作与犹豫位置；三关自动通过不能证明已经上瘾。

## 13 静态发布与回滚

当前公开入口为 `http://106.12.167.253/tile-explorer/`，运行的是 v0.3 静态 H5。v0.4 仍按同一轻量部署方式，不需要增加游戏 Python 常驻服务。

1. 从确定的源码提交与共享清单导出至专用目录；给出源码 SHA、内容版本、文件清单与逐文件校验值。
2. 静态文件不包含 `.local`、玩家存档、SSH 信息、密码、开发文件或无关附件。
3. 在本机内置浏览器检查，然后放到服务器独立预览目录，例如 `/tile-explorer-v04-preview/`，验证相对路径和三关流程。预览使用独立存储 scope，避免与同源正式版相互覆盖进行中记录。
4. 正式包完整放入不可变目录 `/tile-explorer/releases/<buildId>/`；HTML、脚本、样式、内容和素材共同位于该目录，继续使用包内相对路径。发布后不覆盖此目录，修订必须使用新的 buildId。
5. 稳定入口 `/tile-explorer/` 通过带 `Cache-Control: no-store` 的 HTTP 302 指向当前版本目录。只切换入口指向；发布配置先备份、检查 Nginx 语法，再平滑加载，保留原站点和其他容器。首次切换前也为当前 v0.3 备份建立可访问的完整版本目录，并保留旧页面依赖的原路径资源。
6. 版本目录的资源可采用长期缓存，因为 URL 和内容固定；保留旧目录供已打开的旧标签页和回滚使用。这样不需要在清单路径中追加查询参数，也不会让旧 HTML 在切换时抓到新 JS。清理旧包必须作为单独维护动作，不随发布自动删除。
7. 从公网再次试玩，检查原站点仍正常、自动启动配置仍有效。失败时将稳定入口指回上一完整版本；两个版本的存档 key 隔离，回滚不需要删除玩家数据。

服务器当前使用 HTTP；没有配置 HTTPS 时，预览与验收地址明确使用 `http://`。游戏预览按用户偏好直接在内置浏览器打开并保留标签页。设计文档阶段不改变当前线上游戏。

## 14 主要风险与处理

| 风险 | 处理原则 |
|---|---|
| 换成多图形后出现新死局 | 改 family 分配／遮挡布局并完整重验，保留失败复现；不靠限制玩家动作掩盖 |
| 成品仍像基础牌，玩家期待继续合成 | 明显造型变化＋立即交付＋目标点亮，棋盘不留成品 |
| 教程强迫唯一解或不断打断 | 读真实状态、一次一动作、手势优先、能力记忆、随时求助 |
| 视觉改版使手感回退 | 复用统一坐标、保留节点与事件取消；将连拖、回位、实际释放坐标列为回归门槛 |
| 修改配方却错误接受旧存档 | 新规则与新前缀，玩法 hash 包含配方；只用实际内核合法回放 |
| 素材变多导致加载与维护混乱 | 内容注册表和唯一资源清单，统一风格、素材 ID 与导出引用检查 |
| 方案逐渐扩成大系统 | 先完成三关、三条关系和教学闭环，其他主题保留为后续内容候选 |
